# 运行.md — 怎么把它跑起来（照抄命令版）

> 先说结论：**正式聊天界面归 MaxKB**（本机没 Docker，跑不了）。但项目已经自带了一个联调用对话页，所以你现在就能问：
> - **想看它答问题** → 做「第 1 步～第 5 步」，最后一条命令会把答案直接打印给你。
> - **想自己随便问** → 做「第 6 步」，起服务后打开 `http://127.0.0.1:8000/chat`，像聊天一样输入即可（无需安装任何前端）。

全程不需要 Docker，不需要 MySQL，不需要大模型 Key。

---

## 第 1 步：打开终端

按 `Win + R`，输入 `powershell`，回车。
（如果你用的是 Git Bash 也一样，只有第 2 步的路径写法不同。）

---

## 第 2 步：进入项目目录

PowerShell 里粘贴这一行，回车：

```powershell
cd D:\LLMProject\shopping\shopping-backend
```

Git Bash 里粘贴这一行：

```bash
cd /d/LLMProject/shopping/shopping-backend
```

成功的样子：命令行的路径变成 `...shopping-backend>` 就对了。

---

## 第 3 步：装依赖（只有第一次需要，大概 1 分钟）

```powershell
uv sync --group dev
```

成功的样子：最后几行出现 `Installed NN packages`，没有 `error` 字样。

> 提示 `uv : 无法将uv项识别为...` → uv 没装好，或终端没重开。关掉终端窗口重新打开再试一次；还不行就用 `pip install uv` 后再回来。

---

## 第 4 步：准备演示数据

```powershell
uv run python scripts/init_db.py
```

成功的样子：屏幕输出一段英文字段的数据统计，重点看这几个数字：

```
"goods": 12,        ← 12 个商品
"stock": 11,        ← 11 条库存
"coupon": 9,        ← 9 张优惠券
"preferences": 5    ← 5 条用户偏好
```

最后一行会提示：`Next: uv run python scripts/run_demo.py` —— 就是第 5 步。

> 这一步做的事：把商品、库存、优惠券写进 `data/business.db` 这个 SQLite 文件里（就是"简单的数据库"）。

---

## 第 5 步：跑通全流程，直接看它答题（最关键的一步）

```powershell
uv run python scripts/run_demo.py
```

它会自己做三件事：启动两个服务 → 连续问 7 个问题 → 关掉服务。你要做的只是等它跑完（十几秒）。

成功的样子：中间 7 行都是 `[PASS]`，最后一行是：

```
7/7 用例通过
```

中间还会打印一段**真实回答**，长这样：

```
为你找到 3 款 2000 元以内的手机在售商品：
1) realme GT Neo 6 5G 手机 ¥1599.00｜仅2件（紧张）｜realme
2) Redmi Note 13 Pro 5G 手机 ¥1699.00｜现货12件｜Redmi
3) Redmi K70 5G 手机 ¥2000.00｜现货20件｜Redmi
可用券：满¥1500.00减¥100.00（券码 M1500_100，2026-12-31 前有效）｜适用：realme GT Neo 6 5G 手机、Redmi Note 13 Pro 5G 手机
可用券：满¥2000.00减¥150.00（券码 M2000_150，2026-12-31 前有效）｜适用：Redmi K70 5G 手机
想只看有货的、或者换个预算再筛一次，告诉我就行。
```

看到这 7 个 PASS，就说明**业务流程已经用 SQLite 跑通了**。

---

## 第 6 步：想自己随便问？打开自带的对话页

**6.1 先起服务**（这一步会一直占着这个终端窗口，别关）：

```powershell
uv run python -m uvicorn shopping_backend.agent_api.main:app --host 127.0.0.1 --port 8000
```

看到 `Application startup complete` 就是起来了。

**6.2 浏览器打开这个地址**（项目自带的联调对话页，不用装任何前端）：

```
http://127.0.0.1:8000/chat
```

**6.3 直接问**：

1. 页面顶上三个框分别是 `token`、`user`、`session`：
   - `token` 默认已填 `dev-token`（就是 `.env` 里的 `AGENT_INTERNAL_TOKEN`），一般不用动；
   - `user` / `session` 也已自动生成并记在浏览器里，**同一个 session 连着问才有续问效果**；
2. 底部输入框打字，回车或点「发送」；也可以直接点上面那排灰色快捷问句；
3. 每条回答下面自动展开**调试面板**，这是这页存在的意义：
   - `route_trace`：这一问真的走了哪几步（`supervisor → goods_worker → stock_worker → …`）；
   - `degraded`：`false` 才是真答案；`true` 说明数据没取到，正文是安全话术；
   - `goods / coupons / dropped_rows / grounding_drops`：拿了几条、护栏丢了几条；
     其中 **`grounding_drops` 不为 0 必须排查**（意味着话术里有库里查不到的数字或 ID）；
   - 商品表格：`价格(分)` 与话术里的 `¥` 对照，肉眼确认"说的数就是库里的数"。

**6.4 验证续问能力**（这是 checkpoint 的效果，不是页面缓存）：

同一个 `session` 里先问 `推荐 2000 元以内的手机`，紧接着问 `第二款有货吗` ——
第二问只会返回一款商品，且它的价格正好等于第一问里中间那款。想断开连续性，点「新会话」。

**6.5 停止服务**：回到那个终端窗口，按 `Ctrl + C`。

**6.6 备用：接口级调试页**

想看原始 JSON、或要逐字段试请求体格式，用 FastAPI 自带的接口文档页：
`http://127.0.0.1:8000/docs` → `/api/shopping-agent/run` → **Try it out** →
`Authorization` 填 `Bearer dev-token` → 请求体改成 `{"user_id":"u_1001","session_id":"s_test","query":"有什么满减活动"}` → **Execute**。
（`/chat` 这个页面刻意不出现在这份 OpenAPI 里，因为它不是给 MaxKB 调用的接口。）

## 第 7 步（可选）：换个问题试试这几句

上面 6.3 的框里依次换成这些 `query`，能覆盖主要分支：

| 问法 | 你会看到什么 |
| --- | --- |
| `推荐 2000 元以内的手机` | 3 款手机，都带价格和现货数 |
| `Redmi Note 13 Pro 有货吗` | 只回答这一款的库存情况 |
| `这款卖断了的耳机有优惠券吗` | 说它无现货，同时给出能用的券 |
| `有什么满减活动` | 只列当前有效的优惠 |
| `推荐 5000 元以内的电视` | 老实说没找到，并让你换个说法（不会瞎编） |
| `帮我下单买第一个` | 拒绝：只负责查询和推荐，不下单 |

## 出错了怎么办（人话版）

| 屏幕上看到 | 实际意思 | 怎么办 |
| --- | --- | --- |
| `7/7 用例通过` | 一切正常 | 无需处理 |
| 某几行 `[FAIL]` | 某个环节没跑通 | 看那行下面一行的说明，并发给我 |
| `数据库文件里已有数据` 之类 | 之前跑过，正常提示 | 忽略即可 |
| `401` / `调用凭证无效` | 没填 `Bearer dev-token` | 回 6.3 第 2 项填上 |
| `422` / `请求参数不合法` | 那段 JSON 写错了（比如少了引号、`query` 是空的） | 用第 7 步的示例句子整个替换 |
| 浏览器打不开 `127.0.0.1:8000` | 服务没起，或 6.1 那条命令的窗口被关了 | 重新执行 6.1，看到 `Application startup complete` 再刷新浏览器 |
| `Address already in use` / 端口被占 | 8000 端口已被别的程序占着（可能上一次没关干净） | 把端口号换成 8010：`--port 8010`，浏览器也相应改成 `http://127.0.0.1:8010/docs` |
| `暂时无法获取商品信息，请稍后再试` | 服务在跑，但它取不到业务数据 | 先回第 4 步确认 `goods: 12` 存在，再重新执行第 6 步 |
| PowerShell 里 `cd D:\...` 报错 | 你在用 Git Bash，路径写法不同 | 用第 2 步里 `/d/LLMProject/...` 那一行 |

想彻底重来一遍（把数据和会话记录清空）：

```powershell
uv run python scripts/reset_db.py --yes
uv run python scripts/init_db.py
```

## 附：想改点什么再往下看（不改也完全能跑）

配置文件是项目根目录下的 `.env`（没有就复制一份 `.env.example` 改名为 `.env`）。常用的只有这几个：

| 想要 | 改哪一行 |
| --- | --- |
| 让大模型来理解问题（需要 Key） | `AGENT_MODE=llm` + `OPENAI_API_KEY=你的Key` |
| 让服务之间真的走 HTTP 网络调用 | `BACKEND_DRIVER=http`（同时要把业务后端也起起来，端口 8001） |
| 以后接你们自己的 Java 后端 | `BACKEND_DRIVER=http_java` + `BUSINESS_API_BASE_URL=http://Java的地址` |
| 以后换成 MySQL | `DATABASE_URL=mysql+pymysql://用户:密码@地址:3306/库名`，然后 `uv sync --extra mysql` + `uv run alembic upgrade head`（详细步骤在 `docs/EXTENSION_DB_DOCKER.md`） |
| 不想每次带 token | `AGENT_INTERNAL_TOKEN=`（等号后留空） |

**为什么默认是 rule_based？** 因为你的核心目标是"先用简单数据库跑通业务流程"。默认模式下，意图判断和路由都由代码规则决定，不依赖任何模型也能完整走通；等有 Key 了把 `AGENT_MODE` 改成 `llm`，图的结构、路由分支、数据校验规则一个字都不用变。

**为什么只有联调页、没有正式前端？** 按 `frame.md` 的分工，聊天界面、用户登录、会话记录都由 MaxKB 负责，本服务只作为 MaxKB 里的一个"外部 HTTP 工具"被调用。MaxKB 需要 Docker 部署，你本机没有，所以项目自带了 `http://127.0.0.1:8000/chat` 这个联调页顶上（零构建、单文件、只连同源接口）；等 MaxKB 可用时，按 `docs/MAXKB_INTEGRATION.md` 配上工具即可，本服务与这个页面都不用改。页面本身的设计与后续施工单见 [`实现方案.md`](实现方案.md)。
